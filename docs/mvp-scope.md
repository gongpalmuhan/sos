# SOS MVP 제품 계약 — Step 1

## 0. 문서의 범위와 가정

이 문서는 SOS의 MVP에서 사용자에게 약속하는 문제 범위, 행동 흐름, AI 안전장치, 측정 기준을 고정한다. 구현 기술, 데이터 저장 방식, 화면 설계, 계정 설정은 다루지 않는다.

**가정**

- 대상 사용자는 GitHub 계정으로 로그인할 수 있고, 공개적으로 열람 가능한 GitHub 저장소와 이슈를 대상으로 기여한다.
- 온보딩의 스택 추론은 사용자가 GitHub에서 접근 가능한 기존 저장소의 언어·의존성 신호를 이용한다. 추론값은 확정값이 아니며 사용자가 반드시 확인하거나 수정할 수 있다.
- MVP의 "이슈에 기여 의사를 코멘트"하는 행위는 사용자가 내용을 확인한 뒤 GitHub에서 직접 게시한다. SOS는 자동 게시하거나 사용자를 대신해 이슈·PR을 만들지 않는다.

## 1. 제품 목적과 비목표

### 목적

SOS는 오픈소스에 처음 기여하려는 한국어 사용자가 **첫 PR을 머지하고, 다음 기여를 시도할 수 있는 상태**에 이르도록 돕는 가이드 서비스다. 이를 위해 사용자가 다음 네 가지를 스스로 판단·수행하도록 지원한다.

1. 환영받을 가능성이 높은 저장소와 작은 이슈를 고른다.
2. 이슈의 기존 논의와 작업 맥락을 원문 근거와 함께 이해한다.
3. PR 전에 기여 의사를 예의 있게 알리고, 기여 절차를 따른다.
4. 연결한 PR의 결과와 첫 리뷰 경험을 기록으로 남긴다.

### 비목표

- 사용자가 코드를 이해하거나 수정하는 일을 AI가 대신하는 도구가 아니다.
- PR 제출 수를 늘리는 자동화 서비스가 아니다.
- 메인테이너에게 답변·리뷰·병합을 요청하거나 압박하는 서비스가 아니다.
- 랭킹, 경쟁, 공유를 통한 기여 독려 서비스가 아니다.

성공은 생성된 첫 PR 수가 아니라 **첫 PR의 머지**와 **두 번째 기여로 이어질 가능성**으로 판단한다.

## 2. MVP 사용자와 핵심 문제

### MVP 사용자 정의

다음 조건을 모두 만족하는 한국어 사용자다.

- 오픈소스 기여 경험이 없거나, 머지된 기여가 아직 없는 사람
- GitHub 계정으로 공개 저장소의 이슈와 PR을 열람할 수 있는 사람
- 작은 이슈를 선택하고, 영어로 기여 의사를 표현하며, 자신이 작성한 변경으로 PR을 제출하려는 사람

### 해결하려는 핵심 문제

| 사용자 문제 | MVP의 해결 약속 |
| --- | --- |
| 어디에 무엇을 기여해야 할지 모른다. | 건강도와 초보 적합도를 설명한 저장소·이슈 후보를 제시한다. |
| 이미 논의된 내용과 피해야 할 중복 작업을 파악하기 어렵다. | 유사/닫힌 이슈, PR, 코멘트의 요약과 원문 링크를 함께 제공한다. |
| 메인테이너에게 어떤 말로 시작해야 할지 모른다. | 이슈 맥락을 반영한 영어 코멘트 초안을 제공하되, 사용자가 직접 검토·게시하게 한다. |
| 기여 절차와 리뷰 상태를 놓친다. | fork부터 PR까지의 체크리스트와 연결 PR의 상태를 한곳에서 보여 준다. |

핵심 가설은 다음과 같이 검증한다.

1. 이슈 선택과 첫 소통의 불확실성이 낮아지면 기여 포기가 줄어든다.
2. 환영받는 저장소의 작은 이슈, 근거 있는 맥락 리포트, 한국어 지원은 첫 PR 머지율을 높인다.
3. 첫 PR이 머지된 사용자는 두 번째 기여를 할 가능성이 높다.

## 3. 핵심 사용자 여정

| 단계 | 사용자 행동 | SOS의 책임 | 다음 단계로 갈 수 있는 완료 조건 |
| --- | --- | --- | --- |
| 1. 로그인 | GitHub 로그인에 동의한다. | 읽기 전용 최소 권한임을 표시하고, 쓰기 권한을 요구하지 않는다. | 로그인한 계정의 공개 열람 범위에서 온보딩을 시작할 수 있다. |
| 2. 온보딩 | 자동 추론된 관심 스택을 확인·수정한다. | 저장소 언어·의존성 신호로 스택 후보를 제시하고, 확정 전 사용자 확인을 받는다. | 사용자가 적어도 하나의 스택을 확인 또는 수정하여 저장한다. |
| 3. 저장소 탐색 | 필터와 건강도 점수를 보고 저장소를 고른다. | 50~100개 큐레이션 저장소와 점수의 이유를 제공한다. | 사용자가 저장소 하나를 선택한다. |
| 4. 이슈 선택 | 추천 이유와 난이도를 비교하여 이슈를 고른다. | 규칙 기반 추천, 유형·난이도·초보 적합도·제외 사유를 제시한다. | 사용자가 이슈 하나를 `관심 이슈`로 지정한다. |
| 5. 맥락 확인 | 리포트의 요약과 원문을 읽는다. | 관련 이슈·PR·코멘트의 사실 요약마다 원문 링크를 붙인다. | 사용자가 리포트를 열어 보고, 기여 여부를 판단할 수 있다. |
| 6. 기여 의사 표현 | 영어 초안을 검토·수정하여 이슈에 직접 코멘트한다. | 초안을 제공하고, 먼저 코멘트하는 흐름을 기본값으로 안내한다. | 사용자가 게시 사실을 표시하거나, 게시하지 않기로 결정한다. 게시하지 않은 경우에도 여정을 중단·재선택할 수 있다. |
| 7. 작업 및 PR 준비 | CONTRIBUTING 안내를 따라 작업하고 PR을 직접 연다. | CONTRIBUTING.md의 한국어 요약과 fork~PR 체크리스트를 제공한다. | 체크리스트에서 PR 생성 전 필수 항목을 완료하고, PR URL을 연결한다. |
| 8. 리뷰·병합 추적 | 리뷰 코멘트를 확인하고 대응한다. | 리뷰 코멘트의 한국어 해석과 연결 PR 상태를 제공한다. | 연결 PR이 `merged`, `closed without merge`, 또는 `open` 상태로 확인된다. |
| 9. 기록과 다음 기여 | 결과와 저장소의 첫 리뷰 시간을 확인한다. | 여정 진행도, 머지된 기여, 저장소 평균 첫 리뷰 시간을 보여 준다. | 병합 결과를 기록하고, 다음 기여를 시작할 수 있는 상태가 된다. |

## 4. 포함 기능 계약

| 기능 | 사용자 가치 | 입력 | 출력 | 완료 조건 |
| --- | --- | --- | --- | --- |
| GitHub 로그인 | 별도 가입 없이 공개 GitHub 맥락을 연결한다. | 사용자의 OAuth 동의 | 로그인 상태와 읽기 전용 권한 고지 | 쓰기 권한 없이 로그인되며, 권한 범위가 사용자에게 명시된다. |
| 스택 온보딩 | 자신의 경험에 맞는 후보를 빠르게 좁힌다. | 접근 가능한 저장소의 언어·의존성 신호, 사용자 수정 | 확인 가능한 스택 후보 | 각 후보의 추론 근거가 표시되고, 사용자가 수정·확정할 수 있다. |
| 큐레이션 저장소 목록 | 처음 기여하기 좋은 탐색 범위를 얻는다. | 사전 큐레이션된 50~100개 저장소, 스택·필터 조건 | 필터된 목록과 건강도 점수·점수 이유 | 목록 전체 수가 50~100개이고, 각 저장소에 필터 가능한 분류와 사람에게 읽히는 점수 이유가 있다. |
| 이슈 추천 | 지금 시도할 만한 작은 작업을 고른다. | 선택 저장소, 확인한 스택, 이슈 메타데이터와 규칙 | 추천 순서, 유형·난이도·초보 적합도, 추천/비추천 이유 | 모든 추천 이슈에 분류와 최소 한 개의 추천 이유가 있으며, 규칙상 제외된 이슈는 추천하지 않는다. |
| 맥락 리포트 | 중복 작업과 숨은 맥락을 피한다. | 선택 이슈, 유사·닫힌 이슈, PR, 코멘트 | 핵심 맥락 요약과 각 주장별 원문 링크 | 사실 또는 해석을 담은 각 항목에 하나 이상의 대응 원문 링크가 있고, 링크 없는 주장은 리포트에 포함하지 않는다. |
| 기여 체크리스트 | 절차를 놓치지 않고 PR을 준비한다. | 저장소의 CONTRIBUTING.md와 선택 이슈 | fork부터 PR까지의 순서형 체크리스트, CONTRIBUTING 한국어 요약 | 체크리스트에 fork, 로컬 준비, 변경, 테스트/검증(문서에 명시된 경우), PR 생성 전 확인이 포함되고, CONTRIBUTING 요약은 원문 링크를 가진다. |
| 소통 보조 | 영어 소통의 시작과 리뷰 이해를 돕는다. | 이슈 맥락과 사용자 의도 / 리뷰 원문 | 편집 가능한 영어 이슈 코멘트 초안 / 한국어 해석 | 초안은 자동 게시되지 않고, 사용자가 수정할 수 있다. 해석은 대응하는 원문 코멘트 링크를 함께 제공한다. |
| 진행 추적 | 기다려야 할 일과 결과를 분명히 안다. | 사용자가 연결한 PR URL | PR의 현재 상태와 상태 변경 시점 | 연결한 PR마다 `open`, `merged`, `closed without merge` 중 하나의 현재 상태가 확인된다. |
| 개인 기록 | 첫 경험을 되돌아보고 다음 기여를 준비한다. | 여정 단계, 연결 PR 상태, 저장소의 과거 PR 반응 정보 | 여정 진행도, 머지된 기여 목록, 저장소 평균 첫 리뷰 시간 | 진행도는 여정의 완료/미완료 단계를 구분한다. 평균 첫 리뷰 시간에는 산출 기준과 대상 기간/표본 범위를 표시한다. |

### 건강도와 초보 적합도 표시 원칙

- 건강도 점수는 순위만 보여 주지 않고, 최소한 최근 활동, 이슈/PR에 대한 반응, 기여 안내 존재 여부처럼 사용자가 판단할 수 있는 근거를 함께 표시한다.
- 초보 적합도는 이슈의 크기·명확성·기여 안내·최근 소통 신호를 바탕으로 한 분류이며, "머지 보장" 또는 "응답 보장"으로 표현하지 않는다.
- 추천은 규칙 기반 필터의 결과다. AI가 근거 없이 적합도를 단정하거나 추천 순서를 바꾸지 않는다.

## 5. 명시적 비목표와 제외 이유

| 제외 항목 | 제외 이유 |
| --- | --- |
| 소스 코드 탐색 모드 | 첫 MVP의 문제는 코드 위치 탐색 이전의 이슈 선택·맥락·소통 불확실성이다. |
| 코드 위치 탐색 에이전트 | 코드 분석의 정확성·안전성 범위를 별도로 검증해야 하며, 현재의 첫 기여 흐름에 필수 요건이 아니다. |
| 공유 카드, 아티클 큐레이션, 커뮤니티 통계 | 개인의 첫 기여 실행을 돕는 핵심 흐름을 직접 완료시키지 않는다. |
| 리더보드와 PR 개수 경쟁 | PR 수 경쟁은 성급한 제출과 메인테이너 부담을 유발할 수 있고, 머지와 재기여라는 성공 정의와 맞지 않는다. |

## 6. AI가 할 수 있는 일과 하면 안 되는 일

| AI가 할 수 있는 일 | AI가 하면 안 되는 일 |
| --- | --- |
| 링크된 원문 범위 안에서 이슈·PR·코멘트의 맥락을 한국어로 요약한다. | 원문 근거 없이 저장소 상태, 이슈 원인, 메인테이너 의도, 머지 가능성을 사실처럼 단정한다. |
| 사용자가 검토·수정할 수 있는 영어 이슈 코멘트 초안을 만든다. | 사용자를 대신해 이슈 코멘트, PR, 리뷰 답변을 자동 게시·생성·제출한다. |
| 리뷰 코멘트를 한국어로 해석하고 원문과 연결한다. | 리뷰 지시를 임의로 해석해 코드 변경 지시나 해결책을 확정한다. |
| CONTRIBUTING 원문의 절차를 한국어 체크리스트로 정리한다. | 원문에 없는 테스트, 규칙, 권한, 기여 절차를 만들어 낸다. |
| 명시된 규칙으로 이슈를 분류하고 추천 이유를 설명한다. | 추천 결과를 "안전", "쉬움", "머지 보장"으로 과장하거나, 필터 제외 사유를 숨긴다. |

기본 행동은 **PR을 먼저 만들게 하는 것이 아니라, 이슈에 기여 의사를 직접 코멘트하도록 돕는 것**이다. 사용자가 코멘트를 게시하지 않으면 SOS는 PR 생성을 유도하지 않고, 이슈를 다시 검토하거나 다른 이슈를 선택할 수 있게 한다.

## 7. AI 출력의 근거·검증 요구사항

AI 출력은 사용자 행동을 바꾸는 정보이므로 다음 계약을 만족해야 한다.

1. **근거 연결:** 이슈 맥락, CONTRIBUTING 요약, 리뷰 해석, 저장소 건강도 설명에 포함된 사실·해석·수치는 대응하는 원문 링크를 가져야 한다. 링크가 없으면 해당 주장을 출력하지 않는다.
2. **출처 식별:** 링크마다 출처 종류(이슈, 닫힌 이슈, PR, 코멘트, CONTRIBUTING)와 원문 제목 또는 식별자를 함께 표시한다.
3. **스키마 검증:** 사용자에게 보이기 전 출력 유형별 필수 필드를 확인한다.

| 출력 유형 | 필수 필드 |
| --- | --- |
| 이슈 추천 | 이슈 식별자/링크, 유형, 난이도, 초보 적합도, 추천 이유, 적용 규칙 또는 제외 사유 |
| 맥락 리포트 | 요약 항목, 항목별 근거 링크, 출처 종류, 확인 불가 사항 |
| CONTRIBUTING 요약 | 절차 항목, 원문 링크, 원문에 없음을 표시한 미확인 항목 |
| 영어 코멘트 초안 | 사용자 의도에 맞는 초안 본문, 편집 가능 표시, 자동 게시되지 않음 표시 |
| 리뷰 해석 | 한국어 해석, 대응 원문 코멘트 링크, 불명확한 표현 표시 |
| 건강도/첫 리뷰 시간 | 값 또는 분류, 산출 근거, 대상 기간, 표본 범위, 확인 시점 |

4. **검증 실패 처리:** 필수 필드나 근거 링크가 빠진 출력은 완성 결과로 노출하지 않는다. 대신 "확인할 근거가 부족함"과 부족한 항목을 표시한다.
5. **불확실성 표시:** 원문만으로 결론 낼 수 없는 내용은 추측으로 메우지 않고, `확인 불가` 또는 `사용자 확인 필요`로 표시한다.

## 8. 첫 단계에서 추적할 핵심 이벤트

이벤트는 행동을 재현·비교할 수 있는 이름으로 기록한다. 이벤트 수집은 사용자의 코드나 GitHub 콘텐츠를 변경하지 않는다.

| 이벤트 이름 | 의미 |
| --- | --- |
| `github_login_completed` | 사용자가 읽기 전용 GitHub 로그인을 완료했다. |
| `onboarding_stack_confirmed` | 사용자가 추론된 스택을 확인 또는 수정해 확정했다. |
| `curated_repo_viewed` | 사용자가 큐레이션 저장소 상세 또는 목록에서 저장소를 확인했다. |
| `repo_selected` | 사용자가 기여 후보 저장소를 선택했다. |
| `issue_recommendations_viewed` | 사용자가 이슈 추천 목록을 확인했다. |
| `issue_selected` | 사용자가 관심 이슈를 하나 지정했다. |
| `context_report_viewed` | 사용자가 해당 이슈의 맥락 리포트를 열었다. |
| `contribution_intent_draft_generated` | 이슈 기여 의사 영어 초안이 생성됐다. |
| `contribution_intent_marked_posted` | 사용자가 이슈에 기여 의사를 게시했다고 SOS에 표시했다. |
| `checklist_started` | 선택 이슈의 기여 체크리스트를 시작했다. |
| `pr_connected` | 사용자가 자신의 PR URL을 여정에 연결했다. |
| `pr_status_observed` | 연결 PR의 상태를 확인했다. 상태 값은 `open`, `merged`, `closed_without_merge`다. |
| `first_pr_merged` | 사용자의 연결된 첫 PR이 `merged` 상태로 확인됐다. |
| `second_contribution_started` | 첫 PR 머지 후 사용자가 다른 이슈를 선택하거나 새 PR을 연결해 두 번째 기여를 시작했다. |

`contribution_intent_marked_posted`는 게시 사실에 대한 사용자 표시이고, SOS가 게시를 수행했다는 뜻이 아니다. 첫 PR 머지율은 `pr_connected` 사용자 중 `first_pr_merged`에 도달한 사용자의 비율로 정의한다. 두 번째 기여 가능성은 `first_pr_merged` 이후 `second_contribution_started`가 발생한 비율로 관찰한다. 관찰 기간과 최소 표본은 이번 Step에서 정하지 않는다.

## 9. MVP 완료 판단 기준

MVP는 다음을 모두 충족할 때 제품 범위가 완료된 것으로 판단한다.

1. 4절의 모든 포함 기능이 각 행의 완료 조건을 만족한다.
2. 신규 사용자가 로그인 → 스택 확인 → 저장소/이슈 선택 → 근거 있는 맥락 확인 → 기여 의사 코멘트 초안 검토 → 체크리스트 → PR 연결 → 병합 상태 확인의 전체 흐름을 수행할 수 있다.
3. 추천, 맥락 리포트, CONTRIBUTING 요약, 리뷰 해석, 건강도/첫 리뷰 시간에서 근거 링크와 필수 스키마 필드 누락 시 완성된 AI 결과가 노출되지 않는다.
4. SOS는 쓰기 권한을 요구하지 않으며, 이슈·PR·코멘트를 자동으로 게시하지 않는다.
5. 8절의 핵심 이벤트가 각 정의된 사용자 행동에서 구분되어 기록되어, 세 핵심 가설을 나중에 측정 가능한 형태로 남긴다.
6. 제외 기능이 MVP 흐름에 포함되지 않고, 첫 PR 개수나 리더보드를 성공 지표로 사용하지 않는다.

이 기준은 기능 범위 완료 기준이다. 가설이 참인지에 대한 통계적 결론, 목표 머지율, 두 번째 기여 관찰 기간은 운영 데이터가 쌓인 뒤에 별도로 결정한다.

## 10. 지금 결정하지 않아도 되는 항목과 이후 결정할 항목

### 지금 결정하지 않아도 되는 항목

- 화면 구조, 시각 디자인, 알림 방식
- 구현 언어·프레임워크·배포 방식
- 데이터베이스 구조, 저장 기간, 내부 운영 도구
- OAuth 설정 절차와 외부 서비스 계정 구성
- 추천/건강도 계산식의 세부 가중치와 AI 모델 선택

이 항목들은 본 문서의 사용자 약속과 완료 조건을 바꾸지 않는 한 다음 단계에서 정한다.

### 이후 결정이 필요한 항목

| 결정 항목 | 결정이 필요한 이유 |
| --- | --- |
| 초기 50~100개 큐레이션 저장소의 선정 기준과 실제 목록 | "환영받는 저장소"의 운영 정의와 목록 품질을 확정해야 한다. |
| 건강도·초보 적합도·이슈 난이도에 쓰는 정확한 규칙과 갱신 주기 | 설명 가능한 추천과 일관된 분류를 운영해야 한다. |
| 유사 이슈/PR/코멘트의 검색 범위와 상충하는 근거의 표시 규칙 | 맥락 리포트의 누락·오해 위험을 관리해야 한다. |
| 첫 리뷰 시간의 계산 기간, 표본 최소치, 결측 처리 | 사용자에게 비교 가능한 값을 제공해야 한다. |
| "두 번째 기여" 관찰 기간, 최소 표본, MVP 가설 판정 기준 | 머지 이후 재기여 가설을 일관되게 평가해야 한다. |
| 사용자가 게시 사실과 PR 연결을 표시하는 정확한 확인 방식 | 자동 게시 없이도 여정 상태를 신뢰성 있게 추적해야 한다. |
